# 车载平衡滚球运动控制系统

2026 年全国大学生电子设计竞赛H题视觉部分代码 — 基于立创庐山派 K230 系列的钢球检测与无线图传系统。

## 写在前面
```
本项目已实现90+fps稳定识别钢球（K230刚上电没发热的时候可达100fps 关闭ide及屏幕显示可以更高） 图传30+fps 。

我们采用的水管内壁为绿色 使用了两个视觉模块（K230 K230D）完成识别与图传内容 完成图传模块前需下载VLC （VLC官网为： https://www.videolan.org/vlc/）

本项目并没有装载到小车上运行，只进行过简单测试，一些行进中可能出现的问题并没有在此项目中解决。

本项目仅供参考讨论。

```

## 硬件架构

```
图传链路：  GC2093 → K230D → H.264/MJPEG → WiFi AP → PC

识别链路：  GC2093 → K230  → 图像处理 → UART → 主控板
```

两块板子独立工作，分别连接各自的摄像头。

| 子系统 | 硬件 | 核心功能 |
|--------|------|----------|
| 无线图传 | 庐山派 Lite K230D + GC2093 | 采集画面 → MJPEG/HTTP → WiFi AP 推流 |
| 钢球检测 | 庐山派 K230 + GC2093 | 识别钢球位置 → 偏移百分比 → UART 输出 |

## 快速开始

### 钢球检测端（K230）

1. CanMV IDE 打开 `k230-detector/main.py`
2. 运行 → 校准模式 → 将绿色凹槽对准绿框（只选取水管内壁部分） → 按 USR 键 （注意：K230与K230D的usr键对应GPIO不一致，在使用时请根据自身硬件调整）
3. 自动标定 HSV → 进入识别模式
4. UART（GPIO 11 TX, GPIO 12 RX, 115200 波特率）输出 `[+12.3]` 格式偏移百分比
5. 无钢球时不发送数据

### 无线图传端（K230D）

1. CanMV IDE 打开 `k230-stream/main.py` → 保存到 SD 卡 `/sdcard/main.py`
2. K230D 上电 → 自动建立 WiFi 热点 `K230D_Ball`（密码 `12345678`）
3. PC 连接热点 → VLC 打开 `http://<此处填入K230D显示的IP地址>/stream` 或浏览器打开 `http://<此处填入K230D显示的IP地址>` （注意：<>也要删掉）

   > **VLC 低延迟设置**：VLC 默认网络缓存 1000ms，会导致明显延迟。需改为 200ms：
   > - 命令行启动：`vlc --network-caching=200 http://<此处填入K230D显示的IP地址>/stream`
   > - 或 VLC → 工具 → 偏好设置 → 左下角"显示设置"选**全部** → 输入/编解码器 → 网络缓存 改为 **200** ms

## 识别管线

```
BGR采集(320×240)
  → ROI提取(145行起, 300×15)  （按照自身硬件情况调整）
  → HSV绿色掩码(自动标定 + 余量)
  → 灰度图 × 非绿色掩码
  → OTSU自适应二值化(EMA平滑 α=0.05)
  → 形态学开运算(1×5横向核) （反光在管壁上一般是横向的）
  → 面积过滤(10~250)        （按照自身硬件情况调整）
  → 形状过滤(宽高比0.6~1.7)  （按照自身硬件情况调整）
  → 贴边过滤(球形态豁免)       （按照自身硬件情况调整）
  → 跳变过滤(MAX_JUMP=20, LOST_TIMEOUT=20)
  → UART发送
```

## 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 检测分辨率 | 320×240 | 分辨率对此情景影响不是很大 调小提高帧率 |
| ROI | X=10 Y=145 W=300 H=15 | 根据水管位置设置 |
| HSV 余量 | H±8 S±20 V±30 | 标定时自动计算 |
| OTSU α | 0.05 | EMA 平滑系数 |
| 面积 | 10~250 | 最小/最大色块面积 |
| 宽高比 | 0.6~1.7 | 球形态范围 |
| 形态学核 | 1×5 矩形 | 断开横向反光粘连 |
| 跳变阈值 | 20 px | 相邻帧最大X位移 |
| 超时帧数 | 20 | 200ms 后重新搜索 |
| UART | 115200 8N1 | GPIO 11(TX) 12(RX) |

## 一些优化建议

1. K230模块传给主控的信息最好包含偏移量（使用偏移量会比代码中的偏移比例更好，偏移量即偏移的像素个数）与速度信息，其中速度可由5帧内的位移除以5帧花费的时间得到（具体使用多少帧需要细调 帧数越少则越接近瞬时速度 但同时识别时的抖动带来的影响也会更大 帧数越多则越稳定 但是太大的帧数对于瞬时速度的计算会不准确 需要找到一个平衡点）
2. 如果水管的反光较为严重，加入偏振片或许可以抑制反光带来的影响
3. 对于要求6，我能想到的做法是，可以通过按键或者串口等方式，编写一个视觉模块端的状态机，进入此状态时，记录当前钢球偏移量（钢球位于某非中心位置），之后取此偏移量对应的点为中心原点，重新定义坐标轴，其余视觉处理逻辑与前几问一致
